# Data Flow: try.php Dashboard → Database Tables → UI

## Complete Data Origin Mapping

---

## 1. `institution_candidates` TABLE

### Where try.php Gets It:
```sql
-- try.php line 80
SELECT c.*, ia.title AS assessment_title, COALESCE(u.school_name, i.name) AS school_name, 
       ea.score as exam_score, ea.status as exam_status
FROM institution_candidates c
LEFT JOIN institution_assessments ia ON ia.id = c.assessment_id
LEFT JOIN institutions i ON i.id = c.institution_id
LEFT JOIN users u ON u.id = c.user_id
LEFT JOIN exam_attempts ea ON ea.id = c.exam_attempt_id
WHERE c.institution_id = :institution_id
```

### Where This Data COMES FROM (UI → Database):

**PRIMARY SOURCE: `apply-popcorn.php`**
- **User action:** User enters applicant name + school + popcorn code at frontend
- **File path:** `backend/apply-popcorn.php` lines 114-152
- **When:** When user clicks "Apply Popcorn Code"
- **Code:**
  ```php
  INSERT INTO institution_candidates (
      institution_id,
      assessment_id,
      user_id,
      full_name = $applicantName,        // User typed this in UI
      email = $userEmail,                // From users table
      exam_attempt_id,                   // Generated by system
      status = 'started',
      invited_at = NOW(),
      created_at = NOW(),
      updated_at = NOW()
  )
  ```

**Data path:**
```
Frontend form (exam_selection.php)
    ↓
User clicks "Apply Popcorn"
    ↓
apply-popcorn.php receives: applicant_name, school_name, popcorn_code
    ↓
INSERT into institution_candidates table
    ↓
try.php queries it
```

**ALSO POPULATED BY: `exam-api.php` submitLessonExam()**
- **When:** After user completes exam
- **Updates these fields:**
  ```php
  UPDATE institution_candidates SET
      exam_attempt_id = ?,       // Links to exam_attempts.id
      status = 'completed',      // Changed from 'started'
      score = ?,                 // Final exam score
      exam_status = 'submitted',
      exam_score = ?,
      time_taken_seconds = ?,
      exam_completed_at = NOW(),
      updated_at = NOW()
  ```

## 3. `exam_attempts` TABLE

### Where try.php Gets It:
```sql
-- try.php line 80 (LEFT JOIN)
LEFT JOIN exam_attempts ea ON ea.id = c.exam_attempt_id
```

### Where This Data COMES FROM (UI → Database):

**CREATED BY: `apply-popcorn.php`**
- **When:** When popcorn code is applied
- **Lines 87-97:**
  ```php
  // Check if user already has a pending exam attempt
  $stmt = $pdo->prepare('SELECT id FROM exam_attempts 
                        WHERE user_id = ? AND exam_id = ? 
                        AND status IN ("pending", "verification", "in_progress")');
  
  // If not, create one:
  $stmt = $pdo->prepare('INSERT INTO exam_attempts 
                        (user_id, exam_id, status, verification_status, ip_address, user_agent)
                        VALUES (?, ?, "verification", "pending", ?, ?)');
  ```

**UPDATED BY: `exam-api.php` submitLessonExam()**
- **When:** User completes and submits exam
- **Lines 605-608:**
  ```php
  UPDATE exam_attempts SET
      status = 'submitted',
      submitted_at = NOW(),
      graded_at = NOW(),
      score = ?,           // ← FINAL SCORE
      passed = ?,
      certificate_id = ?
  ```

**Data flow:**
```
apply-popcorn.php creates exam_attempts with status='verification'
    ↓ (user takes exam)
lessonexam.php keeps it 'in_progress'
    ↓ (user completes exam)
exam-api.php submitLessonExam() updates score, status='submitted'
    ↓
try.php joins it: LEFT JOIN exam_attempts ea ON ea.id = c.exam_attempt_id
```

## COMPLETE UI → DATABASE → try.php FLOW

```
┌─────────────────────────────────────────────────────────────┐
│                    USER INTERACTIONS                         │
└─────────────────────────────────────────────────────────────┘

1. STUDENT APPLIES POPCORN CODE
   ├─ URL: frontend/exam_selection.php
   ├─ Input: Exam type selected (Academic/Business)
   ├─ Submits to: backend/apply-popcorn.php
   ├─ POST data: {applicant_name, school_name, popcorn_code, exam_type}
   └─ Database writes:
      ├─ ✓ INSERT into institution_candidates (status='started')
      ├─ ✓ INSERT/FIND exam_attempts (status='verification')
      └─ ✓ INSERT into popcorn_applications

2. STUDENT COMPLETES VERIFICATION
   ├─ URL: frontend/onboard.php
   ├─ Action: Upload ID, selfie, verification
   ├─ Database writes: exam_verifications table (separate)
   └─ Status: Exam still pending/in_progress

3. STUDENT TAKES EXAM
   ├─ URL: frontend/lessonexam.php
   ├─ Action: Answers questions
   ├─ Submits: Individual answers via backend/exam-api.php
   ├─ Database writes:
   │   └─ INSERT into exam_answers (individual question answers)
   └─ Status: exam_attempts.status still 'in_progress'

4. STUDENT SUBMITS EXAM
   ├─ URL: frontend/lessonexam.php (submit button)
   ├─ Submits to: backend/exam-api.php?action=submit_lesson_exam
   ├─ POST data: {attempt_id, score, correct_answers, time_taken_seconds}
   └─ Database writes (FINAL):
      ├─ ✓ UPDATE exam_attempts (status='submitted', score=FINAL)
      ├─ ✓ UPDATE institution_candidates (status='completed', score=FINAL)
      └─ ✓ INSERT into certificates (status='pending')

5. ADMIN APPROVES CERTIFICATE
   ├─ URL: try.php (admin clicks "Approve" button)
   ├─ Submits to: backend/create-certificate.php
   └─ Database writes:
      └─ ✓ UPDATE certificates (status='approved')

┌─────────────────────────────────────────────────────────────┐
│              try.php QUERIES ALL THIS DATA                   │
└─────────────────────────────────────────────────────────────┘

LINE 53:  SELECT * FROM institution_assessments
          ↑ Admin-created exam definitions

LINE 80:  SELECT FROM institution_candidates
          + LEFT JOIN institution_assessments (exam name)
          + LEFT JOIN institutions (school name fallback)
          + LEFT JOIN users (email, school fallback)
          + LEFT JOIN exam_attempts (score fallback)
          ↑ Candidates data from apply-popcorn.php + exam results

LINE 160: SELECT * FROM certificates
          ↑ Final graded results from exam-api.php submitLessonExam()

LINE 180: SELECT FROM institution_popcorns
          ↑ Admin-created popcorn codes for institution
```

## Table Dependency Map

```
users table (registration/login)
    │
    └──→ institution_candidates (created by apply-popcorn.php)
             │
             └──→ exam_attempts (created by apply-popcorn.php)
                  │
                  └──→ certificates (created by exam-api.php)
                       
institution_assessments (admin-defined exams)
    │
    └──→ institution_candidates (linked via assessment_id)

exams table (system exams)
    │
    └──→ exam_attempts (linked via exam_id)

popcorn_applications (tracking)
    │
    └──→ institution_candidates (populated simultaneously)
```

## Summary: Where Each try.php Data Column Comes From

| What's displayed in try.php | From which table | Set by which UI |
|---|---|---|
| Student name | `institution_candidates.full_name` | apply-popcorn.php (user typed) |
| Email | `users.email` | Login/registration |
| School | `users.school_name` OR `institutions.name` | User profile OR admin setup |
| **Exam name** | `institution_assessments.title` | Admin created |
| **Score** | `institution_candidates.score` OR `exam_attempts.score` | exam-api.php (auto-calculated) |
| **Time taken** | `institution_candidates.time_taken_seconds` | lessonexam.php (timer) |
| **Certificate status** | `certificates.status` | exam-api.php (created), then admin approval |
| **Popcorn codes** | `institution_popcorns.popcorn_code` | Admin created |
| **Completed/Pending status** | `institution_candidates.status` | apply-popcorn.php → exam-api.php |

---

## Critical Point

**Everything displayed in try.php ultimately comes from:**

1. **Admin setup** (institution_assessments, institution_popcorns, institutions)
2. **User application** (apply-popcorn.php) - name, school, email
3. **Exam completion** (exam-api.php submitLessonExam) - scores, status, certificates

**The UI entry points are:**
- `frontend/exam_selection.php` → apply-popcorn.php → institutions_candidates
- `frontend/lessonexam.php` → exam-api.php → exam_attempts + certificates
- Admin interface → institution_assessments (where exams are defined)
